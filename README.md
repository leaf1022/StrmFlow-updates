# StrmFlow 更新公告

本仓库仅提供 StrmFlow 的正式版本公告、更新说明和公开 Docker 镜像信息，不包含私有业务源码。
源码仓库继续保持私有；不需要维护第二套业务代码或第二套版本号。

## 已发布版本

- 正式版本：`v0.1.40`
- 固定镜像：`leaf1022/strmflow:0.1.40`
- 滚动镜像：`leaf1022/strmflow:latest`
- 当前两者指向相同镜像内容；目前仅支持 `linux/amd64`。
- 镜像 digest：`sha256:16800a55d65a4e9a2aa1f025c9b60f88dd08d469a4e7e75471508033dac37e9e`

`latest` 只是最新正式镜像的滚动标签，不会使运行中的容器自动更新。
固定 tag 用户需先调整 Compose 镜像版本；latest 用户可以手动执行：

```bash
docker compose pull && docker compose up -d
```

更新前请备份自己的配置和数据库。本项目不要求挂载 Docker socket，也不会自动拉镜像、重启或部署。

## 0.1.40 更新内容

- 修复监控上传仍在整理或后处理时，源目录被误判为空并删除的问题。
- 上传成功后不再仅凭任务状态解除保护；必须由持久化整理记录与上传任务、远端文件 ID 精确匹配后才释放目录。
- 空目录清理器与转存守望者会跳过仍在处理的上传目录，避免删除中间目录或反复触发未完成轮询。
- 永久识别失败最多尝试 3 次，临时错误最多尝试 8 次；停止自动重试时保留本地与远端文件，并通知到已配置的通知渠道。
- 人工处理提示只包含安全诊断信息，不包含文件 ID、路径、URL、Cookie、签名或原始上游错误。
- 仪表盘优先按容器 cgroup 口径显示工作集，排除可回收页缓存，不再把宿主机总内存当作容器占用。
- 增加 Go Heap、栈、NextGC、协程数和 GC 次数等指标，便于排查长期运行内存问题。

本版本不包含数据库结构变更，不需要手工迁移。

## 更新检测

接入本仓库的后续构建匿名请求本仓库的最新正式 Release，无需私有源码仓库 Token。
启动一分钟后检查，之后每 12 小时检查；可在系统配置里关闭或手动检查。
当前 `v0.1.40` 与 `latest` 均包含公告源接入代码；检测只读取本仓库的公开 Release，不访问私有源码仓库。

## 发布规则

私有源码、镜像和本仓库公告使用同一个版本号。先完成对应源码与镜像发布及验证，再发布相同版本的公告。
这里只发布可公开的说明，不上传私有业务源码、配置、日志、用户数据或凭据。GitHub 自动提供的源码归档只包含本公告仓库内容。
